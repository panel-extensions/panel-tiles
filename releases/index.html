Releases¶

Version 0.5.3¶

Bug Fixes¶

  • Removing or adding a tile no longer re-renders every tile that was in the grid when it first loaded. The grid now tells Panel which tiles it has already rendered, so the other tiles keep their plots and only reflow. (#18)
  • Resizing a tile beside tiles stacked on top of one another now shows the fill and overflow feedback. The room left in the row counted every stacked tile separately, so it came out too small and no feedback was shown at any drag distance. (#19)
  • The grid lays its tiles out again when its width changes without a window resize, for example when a sidebar opens or closes, instead of leaving them overlapping or spread apart. (#20)

Version 0.5.2¶

Bug Fixes¶

  • A grid no longer stays blank for the rest of the session when another component on the page never finishes rendering, for example one removed before it mounted while switching layouts quickly. The grid now waits only for its own tiles instead of the whole page. (#17)
  • A grid laid out while hidden (its own visible=False, a hidden parent or an inactive tab) now lays out its tiles again when shown, instead of leaving them stacked at the top. (#17)
  • A tile that raises an error while rendering no longer leaves the whole grid empty; the error is logged and the other tiles render. (#17)

Version 0.5.1¶

Bug Fixes¶

  • Dragging a tile that already fills its row slightly past the row end now shows the fill outline and row-end marker. Previously the drag snapped straight back to the tile's width without any feedback, so the forgiving resize was invisible on full rows. (#16)
  • The bundle URL now always carries a hash of the bundle, so browsers load the new code after an upgrade instead of reusing a cached bundle from an older release. (#16)

Version 0.5.0¶

New Features¶

  • Forgiving resize: Widening a tile slightly past the end of its row now snaps it to fill the remaining row space exactly instead of reflowing the row. Only dragging further than the new overflow_tolerance parameter (56 pixels by default, 0 for the previous behavior) reflows on release. While resizing, a subtle outline and row-end marker show when the tile fills the row, and past the tolerance a dashed preview shows the released size and the tiles that will move are outlined. Colors follow the theme through the --tile-snap-color and --tile-overflow-color CSS variables. (#15)

Bug Fixes¶

  • Resized tiles no longer jump to another row after snapping to a neighbour's edge. Widths were converted against the grid's rounded width, so on fractional container widths (sidebars, padding, browser zoom) a snapped tile came out a fraction of a pixel too wide. Stored widths are now computed against the real width and rounded down so they always fit. (#15)
  • Resizing no longer shrinks the tile by its margins on every drag, and a height-only resize keeps the tile's width exactly. (#15)
  • Snapping picks the nearest edge on each axis, and snapping to the grid's edge is flush instead of 10px short. (#15)

Version 0.4.0¶

New Features¶

  • Generated responsive layouts: Below the width a layout was arranged at, tiles now wrap onto new lines once they would shrink below half their authored size (wrap_shrink), min_col_width or their own min_width, instead of shrinking proportionally. Works with or without breakpoints. The new reference_width parameter records the authoring width, and responsive_mode="scale" restores the previous behavior.
  • The breakpoint toolbar marks the base band and bands with custom layouts, and a Reset button discards a band's custom layout. TileGrid.reset_responsive_layout() does the same from Python.

Behavior Changes¶

  • responsive_layouts now only holds layouts created by editing a band other than the base band. Previously every edit in AUTO mode, and every switch between bands, copied the displayed layout into the current band.
  • Editing a band preview no longer overwrites layout.
  • A band without a custom layout is generated from layout rather than copied from the next larger band.

v0.3.0 (Upcoming)¶

New Features¶

  • Responsive breakpoint layouts: Define breakpoints (e.g. [768, 1200]) to author per-breakpoint tile arrangements. A toolbar appears in edit mode to switch between breakpoint views, and layouts are stored in the new responsive_layouts parameter. (#278adf3)

Bug Fixes¶

  • Fixed tile opacity not being restored correctly after an error during drag/resize. (#8)

v0.2.0 (2026-06-14)¶

New Features¶

  • min_col_width parameter: Set a minimum tile width in pixels. When the container is too narrow for a tile at its authored percentage, the tile responsively widens to prevent overflow without modifying the persisted layout. (#5)

v0.1.0 (2026-06-04)¶

Initial release of panel-tiles, providing TileGrid, a draggable and resizable grid layout for Panel apps powered by Muuri and interact.js.

Features¶

  • Drag-and-drop tile reordering
  • Resize tiles from the corner handle
  • Configurable layout with percentage-based widths and pixel heights
  • Close buttons with hide or remove behavior via the close_action parameter
  • Persist user layouts to browser localStorage with local_save
  • Read-only mode (editable=False) for fixed dashboards
  • Dynamic add/remove of tiles at runtime
  • Card-style tile appearance with configurable elevation
  • Gap-filling layout algorithm (fill_gaps)
